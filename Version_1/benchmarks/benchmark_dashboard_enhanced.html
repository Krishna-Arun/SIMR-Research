🔬 Benchmark Methodology: How Questions Are Made

Three-Phase Pipeline

1️⃣
Generate
Draft question stem, classify labs into L_core / L_optional / L_irrelevant, ground essential labs in KDIGO guidelines via PubMed citations
2️⃣
Evaluate
Strict 4-criterion check: (A) clinically sound, (B) requires labs, (C) correct lab classification, (D) correct patient context
3️⃣
Rubric
Build full answer rubric (c1–c4 criteria) and lab scoring rubric for approved question. Stored in benchmark manifest.

Evaluator-Optimizer Process (AKI Example)

The generation loop runs for up to 5 rounds. On each round:

Criterion A: Clinically Sound?
The stem must present a realistic clinical scenario without lab values. Rejected if the scenario is contrived or the clinical presentation doesn't support a clear procedural decision.

Criterion B: Requires Labs?
The question must be unanswerable from the clinical presentation alone. The answer must hinge on specific lab values (e.g., potassium level gates RRT decision, not procedural category).

Criterion C: Correct Lab Classification?
L_core labs (essential for the decision) must be cited with KDIGO or clinical guideline support. L_optional labs must have clear secondary relevance. L_irrelevant labs must have no bearing and be justified. All classifications must be grounded in published evidence (PubMed for AKI → KDIGO 2012).

Criterion D: Patient Accuracy?
The demographic and clinical facts stated in the question stem must match the actual MIMIC-IV patient data (age, gender, diagnoses, past medical history). No invented facts.

On REJECTION: The generator receives feedback ("failed on criterion C: lab classification missing KDIGO 2012 Section 5.3 reference for potassium") and regenerates.

On PASS: The generator moves to Rubric phase, building the expected answer rubric (c1: correct procedure named and synonyms; c2: required labs and values; c3: causal chain; c4: patient accuracy).

⭐ How Answers Are Graded

Two-Stage Grading Process

1️⃣
Automatic Scoring
Compute lab_score (0.70 max) based on labs requested + R_core, R_wrong, R_under, R_over, R_justification components
2️⃣
Supervisor Grading
Three agents (Reward, Critic, Optimizer) score answer (1.00 max) on c1–c4 criteria with explanations and optimization feedback

Lab Score (0.70 max) — Formula

lab_score = min(0.70, 0.35·R_core + 0.20·R_wrong + 0.10·R_under + 0.20·R_over + 0.15·R_justification) Penalty Parameters: β=2 (R_under, exponential), α=0.5 (R_over, exponential) Components: R_core = fraction of L_core labs requested & correctly interpreted R_wrong = penalty for L_irrelevant labs cited as drivers (linear) R_under = exponential penalty for missing L_core labs (e^(-β·n_missing)) R_over = exponential penalty for excessive lab requests (1 - e^(-α·n_excess)) R_justification = 0 (absent) | 0.5 (generic) | 1.0 (patient-specific per lab)

Answer Score (1.00 max) — Four Criteria

Reward Agent: Scores c1–c4 on 0–1 scale per rubric criteria
Critic Agent: Explains why each score was assigned; identifies gaps (e.g., "agent cited creatinine but didn't link to KDIGO Stage 3")
Optimizer Agent: (Placeholder for future RL optimization) suggests how answer could have scored higher

Final answer_score = mean(c1, c2, c3, c4) up to 1.00

Total Score = lab_score + answer_score (max 1.70)

🎯 Cardiac Benchmarks: How They're Built

Case Preparation (EHRSHOT Data)

Step 1: Extract EHRSHOT ACS Patients
Query EHRSHOT MEDS database for patients with diagnoses I21.* (acute myocardial infarction) or I24.* (infarction complications) with lab measurements for Troponin I and other cardiac markers.

Step 2: Identify Direction-Reversal Windows
Scan each patient's troponin trajectory for windows where the last 2 visible measurements show one direction (rising/falling/stable) but the next measurement (24-48h gap) reverses. Example: last values are [3.5, 7.8] (rising trend visible), but next value at t+47h is 2.1 (falling).

Step 3: Label Reversal Type & Extract Context
Categorize as rising→falling, falling→rising, stable→falling, or stable→rising. Extract labs up to the "visible" time point (last troponin measurement before reversal), but exclude target troponin and the "gap labs" (measurements between visible and target).

Step 4: Create Condition Variants
Build labs-only variant (only lab measurements) and full-EHR variant (diagnoses, medications, procedures, observations, visit history) to test context restriction impact.

Scoring for Cardiac Benchmarks

case_score = direction_correct * 0.40 + within_50pct * 0.35 + within_20pct * 0.25 direction_correct = 1 if predicted_direction matches ground_truth_direction, else 0 (Threshold: >20% change = direction change, ±20% = stable) within_50pct = 1 if |predicted - actual| / actual ≤ 0.50, else 0 within_20pct = 1 if |predicted - actual| / actual ≤ 0.20, else 0 Baselines: Random direction (3-class problem): 33% accuracy expected Last-value heuristic: Always predicts "stable" → 0% direction accuracy on reversals Trend-extrapolation: Extrapolates visible trend → 0% direction accuracy by construction

📈 What Makes a Good Benchmark?

1. Clear Ground Truth: Every case has an unambiguous correct answer grounded in guidelines (KDIGO for AKI, troponin kinetics for cardiac).

2. Multiple Difficulty Levels: Benchmarks span easy (labs-only with explicit lab set), medium (full-EHR with signal integration), and hard (trend-reversal, noisy context).

3. Faithful to Real Data: All cases extracted from MIMIC-IV and EHRSHOT with minimal synthetic enhancement. Demographics, diagnoses, and lab values are real.

4. Evidence-Based Rubrics: Scoring criteria tied to published guidelines or clinical best practice, not arbitrary metrics.

5. Interpretable Failures: When agents fail, failure modes are diagnostic (e.g., "rising bias", "magnitude anchoring", "recovering signals ignored"), informing model improvements.
